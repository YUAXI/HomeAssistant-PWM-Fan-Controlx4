# 故障排查

[← 首页](Home) · **中文** · [English](Troubleshooting-EN)

## 先做这 4 件事

1. **看串口日志**：Type-C 接电脑，`esphome logs <配置>` 或任意串口工具（115200）打开串口，能看到启动日志说明硬件活着。
2. **看 Web 面板**：`http://<设备IP>/`，能打开说明 Wi-Fi 与固件正常。
3. **看 HA 实体**：设备页里「设备运行时间」是否在增长（归零 = 重启过）。
4. **确认固件版本**：单核/双核刷错是最常见的「开不了机」。

## 设备不启动 / 找不到热点

| 检查 | 说明与处理 |
|:-----|:-----------|
| 供电 | 必须用 DC 12V；Type-C 5V 只能刷写调试，带不动风扇，部分板子在纯 5V 下也无法稳定启动 |
| 固件是否刷错 | `v1.0 双核` 固件刷到单核设备**无法启动**。重新 USB 刷 `v1.0 单核` 或任意 `v2.0` |
| 分区表是否损坏 | 只用 `.firmware.bin`（app 镜像）刷到 `0x0` 会得到不可启动的镜像 → 用 `.factory.bin` 刷 `0x0` |
| 按键误触 | BOOT（IO0）被按住不放会进入下载模式，松开后重新上电 |
| 模组供电 | 摸 ESP32 模组是否发热异常；量 3.3V 轨是否在 3.2–3.4V |

## 串口不识别 / 刷写失败

| 现象 | 原因 | 处理 |
|:-----|:-----|:-----|
| 设备管理器里没有 `CH340` | 缺驱动 / 线是纯充电线 | 装 WCH CH340 驱动；换一根带数据的 Type-C 线 |
| `Failed to connect to ESP32` | 没进下载模式 | 按住 BOOT → 按一下 RST → 松开 BOOT，再执行刷写 |
| `Timed out waiting for packet header` | 波特率过高 | 降到 `--baud 115200` |
| `Serial port busy` / 拒绝访问 | 串口被占用 | 关掉 ESPHome Dashboard、Arduino IDE、串口助手等 |
| 刷写中途失败 | USB 供电不足 / 线材差 | 换 USB 口（优先主板后置口），拔掉风扇负载 |
| Linux 权限错误 | 无串口权限 | `sudo usermod -aG dialout $USER`，重新登录 |

标准救援流程：

```bash
# 1. 进入下载模式：按住 BOOT，点按 RST，松开 BOOT
# 2. 全片刷写 factory 固件
esptool.py --chip esp32 --port COM5 --baud 115200 write_flash 0x0 \
  v1.0-single-core.firmware.factory.bin

# 3. 若还不行，先整片擦除再刷
esptool.py --chip esp32 --port COM5 erase_flash
```

## 配网失败 / 连不上 Wi-Fi

| 现象 | 处理 |
|:-----|:-----|
| 热点 `ESP32-Fan-22810` 不出现 | 设备已在跑旧 Wi-Fi 配置；断电重启后 60 秒内连不上会回到热点模式。或设备根本没启动（见上一节） |
| 192.168.4.1 打不开 | 手机连热点后关闭移动数据；用 `http://` 前缀，别用 https |
| 输完密码一直转圈 | 只支持 **2.4GHz** Wi-Fi，5GHz 连不上；确认密码正确、路由器未开 MAC 白名单 |
| 连上了但很快掉线 | 信号太弱（< −80 dBm）；换位置或加 AP；企业级 Wi-Fi（802.1X）不支持 |
| 改了 Wi-Fi 密码后失联 | 断电重启回落到热点模式，重新配网 |

## HA 发现不了设备

| 检查 | 处理 |
|:-----|:-----|
| 网段 | HA 与设备必须能互相访问；跨 VLAN 时 mDNS 不会通，改用「手动输入 IP」 |
| 浏览器能否打开 `http://<IP>/` | 打不开 → 设备侧问题，不是 HA 问题 |
| API 密钥是否被改过 | 用配置里当前的密钥；不确定就重新刷官方固件 |
| HA 是否装了 ESPHome 集成 | 设置 → 设备与服务 → 添加集成 → ESPHome |
| 端口占用 | 原生 API 用 6053，被防火墙拦时也会失败 |

## 实体重复 / 设备互相覆盖

**原因**：多台设备用了同一个 `name`（旧固件没有 MAC 后缀）。

**处理**：

1. 删除 HA 里旧的 ESPHome 条目；
2. 升级到启用了 `name_add_mac_suffix: true` 的固件（当前全部版本都已启用）；
3. 重新添加设备，此时设备名带 MAC 后缀，多台并存。

## 风扇不转

按顺序排查：

| 步骤 | 检查点 |
|:-----|:-------|
| 1 | HA/Web 里风扇状态是 `on` 吗？速度等级 > 0 吗？ |
| 2 | 手动设到 100% 是否转？——不转说明是供电/接线问题，不是调速问题 |
| 3 | 电源开关是否联动：风扇实体 `on_turn_on` 会打开 `fanN_pwr`（TPS22810 EN）。用万用表量风扇座 Pin2 对 GND 是否有 12V |
| 4 | 风扇是否 4PIN 标准线序？12V/GND 接反会烧器件 |
| 5 | 3PIN 风扇缺 PWM 线时，1% 也可能不转（部分风扇 PWM 悬空 = 全速，部分是停转） |
| 6 | 温度源绑定了吗？`T-Min` 是否高于当前温度？→ 本地闭环会主动断电（见 [温度控制](Temperature-Control#手动控制与本地闭环的冲突)） |
| 7 | `F-Min = 0` 且温度刚过线 → 计算结果为 0%，等价关闭 |
| 8 | 单独给风扇接 12V 是否能转？不能转 = 风扇坏 |

## 转速为 0 或乱跳

| 现象 | 原因 | 处理 |
|:-----|:-----|:-----|
| 开启状态但转速 0 | Tach 线没接 / 风扇无 Tach / 该路 Tach 上拉缺失 | 换 4PIN 风扇；检查 GPIO32/33/25/26 对应焊接 |
| 转速乱跳 ±20% | 低速时脉冲太少（4 秒内脉冲数少，量化误差大） | 属正常；或把 `update_interval` 调大、加 `sliding_window_moving_average` 滤波 |
| 转速恰好一半 | 风扇是 1 脉冲/转 | 把 `multiply: 0.5` 改成 `1.0` |
| 转速恒定高值 | Tach 被干扰/上拉缺失导致误计数 | 检查 10kΩ 上拉与走线 |
| 风扇停了但还有读数 | 滤波残留 | 等一个刷新周期（4s） |

## PWM 啸叫 / 共振

- 25 kHz 是 4PIN 风扇标准，人耳基本听不到，但**电机线圈**在低速时会发出啸叫 —— 把最低速度从 1–5% 提到 20% 以上通常能消除；
- 机箱钣金共振：把风扇换成硅胶垫固定，或错开 4 路风扇的转速（`F-Min` 各差 5%）；
- 若听到的是电源啸叫：TPS5430 在轻载时可能进入跳周期模式，属正常，可加负载或忽略。

## 温控不生效

| 检查 | 说明 |
|:-----|:-----|
| `FN-Src` 是否为「未绑定」 | 默认绑定 A–D，但如果手动设过「未绑定」就不会执行温控 |
| 温度是否为 `unknown` | 探头未接 / 无上拉 / 索引错位 → 算法走「保持当前状态」 |
| `T-Min` ≥ `T-Max` | 固件不校验，会先命中「≤ T-Min → 停转」分支，表现为永远不转 |
| `F-Min = 0` | 刚过线时计算结果为 0% → 视为关闭 |
| 是否在 HA 里手动改过风扇 | 5 秒内会被闭环覆盖，属于正常 |
| 参数是否被改乱 | 用 HA/Web 把 5 个参数恢复到默认值（30 / 50 / 0 / 100） |

## 温度读数异常

| 现象 | 处理 |
|:-----|:-----|
| 全部温度 `unknown` | GPIO14 是否接对、是否有 4.7kΩ 上拉、探头是否 3.3V/5V 供电 |
| 部分 `unknown` | 单个探头接触不良；索引会前移，改用固定 `address` |
| 读数明显偏差 | 长线压降/干扰；改用屏蔽线，缩短总线长度 |
| 温度 A–D 与物理位置对不上 | 索引顺序问题，见 [温度控制](Temperature-Control#索引与温度-ad) |
| 刷新很慢 | 固定 5 秒；4 个探头共用一条总线，属正常 |

## 雷达问题

| 现象 | 处理 |
|:-----|:-----|
| 距离一直 unknown | TX/RX 接反、未供 5V、波特率不对；看日志有没有 `distance:` 行 |
| 一直「有人」 | `Min` 太小 / `Max` 太大；先把区间收到目标范围再观察 |
| 一直「无人」 | 人不在 `[Min, Max]` 内，或静止超过 5 秒被判定为伪目标 |
| 数值抖动 | 雷达分辨率约 1cm，联动时加 `for:` 去抖 |
| 日志刷屏 | `uart.debug` 正常行为，`logger.level: INFO` 即可 |

## Web 面板打不开 / API 404

| 现象 | 原因 |
|:-----|:-----|
| 打不开首页 | IP 变了（看路由器）、端口 80 被占（不可能，是设备自己）、跨网段防火墙 |
| API 返回 404 | 实体名拼错，或没做 URL 编码。名字必须与 YAML `name` **完全一致**（含空格） |
| API 返回 400/405 | 动作名错（应该是 `turn_on`/`turn_off`/`toggle`/`set`/`press`），或该端点用了 GET 去写 |
| 返回 `401` | 配置里启用了 `web_server.auth`，脚本没带认证 |
| 偶尔超时 | 连接数过多 / 设备内存紧张，减少并发与轮询频率 |

## OTA 失败

| 现象 | 处理 |
|:-----|:-----|
| 提示认证失败 | OTA 密码错：`4283bb50a8cd66774ce91d2c9d412cf2` |
| 找不到设备 | 用 IP 而不是主机名；确认在同一网段；`ping` 测试 |
| 传输到一半断开 | Wi-Fi 信号弱、电源不稳；靠近 AP 或改 USB 刷写 |
| 升级后设备失联 | 固件与硬件不匹配（单核/双核），需 USB 救砖 |
| 升级后参数全丢 | 用了 factory 全片刷写，NVS 被清空，重新设置温控参数 |

## 设备频繁重启

| 可能原因 | 排查 |
|:---------|:-----|
| 供电不足 | 4 路风扇同时启动浪涌拉低 12V；换 3A 以上电源，加软启动（错开启动） |
| 5V 轨过载 | 雷达 + 探头 + BLE 负载；量 5V 是否跌破 4.8V |
| 看门狗 / 崩溃 | 串口日志有 `Guru Meditation` / `***ERROR***`；升级到最新固件并回贴日志 |
| 内存不足 | v2.0 雷达版功能最多；减少 Web 连接、去掉 `bluetooth_proxy` |
| 看运行时间 | 归零说明重启；不归零则是网络抖动导致的 `unavailable` |

## CI 编译失败

| 现象 | 处理 |
|:-----|:-----|
| YAML 语法错 | 本地 `esphome config <文件>` 先校验 |
| 组件改名/移除 | CI 用最新 ESPHome，上游大版本升级会破坏旧配置；本地 `pip install -U esphome` 复现后修配置 |
| 找不到固件产物 | `.esphome/build/<name>/` 路径变化；CI 用 `find "$SRC_DIR/.esphome" -name "firmware*.bin"` 兜底 |
| 只在 CI 失败 | 检查是否依赖本地未提交的文件（`.gitignore` 会忽略 `.esphome`） |

## 还有问题？

收集以下信息再提问，定位效率最高：

```text
1. 固件版本（HA 里「ESPHome 版本」实体 / Release 名）
2. 硬件版本（v1.0 / v2.0，单核 / 双核）
3. 串口启动日志（前 40 行 + 报错段）
4. HA 中相关实体的状态截图
5. 复现步骤（做了什么 → 期望什么 → 实际什么）
```
