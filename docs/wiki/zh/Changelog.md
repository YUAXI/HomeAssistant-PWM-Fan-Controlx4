## 升级注意事项

### 从「无 MAC 后缀」固件升级到当前版本

1. HA 中先**删除**旧的 ESPHome 条目（不要用「迁移」，否则会和新设备打架）；
2. OTA 或 USB 刷入新固件；
3. 重新添加设备，此时设备名带 MAC 后缀；
4. 仪表板/自动化里引用旧 `entity_id` 的地方需要重新指向新实体（可以先用「开发者工具 → 实体」搜索确认新 ID）。

### 从 `v1.0` 升级到 `v2.0`

- 硬件不同：v1.0 板子没有 1-Wire 与雷达接口，刷 v2.0 固件后温度/雷达实体永远是 `unknown`（功能不可用但不影响风扇）；
- 反之 v2.0 板子刷归档的 v1.0 单核固件则只是少了扩展功能，风扇控制正常（会闲置一个核心）。

### 单核老设备升级到当前版本

1. 2026-11-12 之后的双核成品直接刷当前双核构建，无需特殊处理；
2. 更早购买的单核板**不能**刷双核固件（会无法启动）。请到 `firmware/zh/archive/` 或 `firmware/en/archive/` 里选对应变体自行编译：
   - v1.0 单核板 → `archive/v1.0/single-core/config.yaml`
   - v2.0 单核板 → `archive/v2.0/single-core/{basic,ds18b20,ds18b20-radar}/config.yaml`
3. 归档构建不在 CI / Release 中，没有现成的 `.factory.bin` 可下；用 USB + `esptool` 刷自己编译出来的 factory 镜像即可。

### 关于「同版本重刷」

Release tag 是构建日期，同一天多次触发 CI 会更新同一个 Release。若需要可追溯的版本，请记录下载时的 tag 与 `ESPHome 版本` 诊断实体。

## 兼容性矩阵

| 固件 | v1.0 硬件 | v2.0 硬件 |
|:-----|:---------:|:---------:|
| v1.0 双核 | ⚠️ 仅双核板 | ⚠️ 仅双核板 |
| v1.0 单核（归档） | ✅ | ✅ |
| v2.0 Basic（双核） | ⚠️ 仅双核板，无扩展功能 | ✅ |
| v2.0 DS18B20（双核） | ⚠️ 仅双核板，无温度接口 | ✅ |
| v2.0 DS18B20+雷达（双核） | ⚠️ 仅双核板，无雷达接口 | ✅ |

> 同一列里「✅」表示功能完整，「⚠️」表示能跑但缺少对应硬件接口、或该板型无法启动。归档单核固件在双核芯片上同样可以正常运行（闲置一个核心）；反过来，双核固件无法在单核板上启动。
